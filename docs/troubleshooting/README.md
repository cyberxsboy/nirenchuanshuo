# Troubleshooting Guides

Document technical problems with enough detail for another person to reproduce and verify the solution.

## Recommended format

1. **Symptoms** — what happens and where.
2. **Environment** — OS, software versions, and relevant configuration.
3. **Possible causes** — distinguish verified causes from hypotheses.
4. **Diagnostic steps** — safe commands and expected observations.
5. **Resolution** — the fix and how to validate it.
6. **Related resources** — official documentation and relevant website articles.

Avoid publishing private logs, IPs where sensitive, credentials, or personal data.
